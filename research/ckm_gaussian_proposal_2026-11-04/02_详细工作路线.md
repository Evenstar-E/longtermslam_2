# 仿真优先的详细工作路线

日期：2026-11-04。资源：目前只有电脑；没有假定机器人、射频硬件、独立服务器或可用CUDA显卡。本文是实施计划，目录、模块、数据集和实验均为拟建设内容，尚未实现。

主方案：[01_研究方案](01_研究方案.md)。文献与创新边界：[03_文献核验与主张边界](03_文献核验与主张边界.md)。

## 1 最先要回答的问题

先用一个会移动的柜子回答：**在变化后不给模型新无线测量，利用变化观测更新的信道预测，是否比旧地图和简单物理重算更有用；当观测不准时，模型能否识别需要补测的位置？**

这一步成立，再引入网络延迟和导航。完整SuperMap、开放词汇VLM、云端服务与复杂SLAM不进入启动依赖。第一篇工作的核心应能在“固定接入点＋模拟场景＋局部平均信道增益”上清楚检验。

建议按约16个全时工作周安排，前8周争取得到核心方法的继续／调整判断，后8周完成网络应用与确认实验。排程只是估计；环境兼容、基线复现和真实视觉输入可能延长时间，以下验收关卡优先于日期。

## 2 软件分工与电脑能力分支

| 组件 | 用途 | 首选实现方向 | 资源限制下的处理 |
|---|---|---|---|
| 场景与RGB-D | 动态物体、相机观测和隐藏几何真值 | 程序化网格场景＋渲染器；统一导出位姿、RGB和深度 | 先生成小场景、少视角；无视觉输入时只报告O／P轨道 |
| 参考RF | 生成场景变化后的参考信道 | Sionna RT，记录版本、路径机制与材料定义 | CPU／LLVM可用性先检查；降低规模、离线生成，不承诺实时 |
| 算法地图 | 实例几何、位姿和RF属性 | 局部高斯＋RF表面代理，另保留同观测网格对照 | CPU上可先验证高斯坐标变换与代理；这不等于完整视觉3DGS训练 |
| RF预测 | 传播近似、属性迁移、不确定性 | 先可解释小模型，再按残差需要增加小网络 | 先用少候选、少假设；记录误差与计算量折衷 |
| 网络标签 | 产生队列、竞争、重传和交付延迟 | ns-3 Wi-Fi＋信道轨迹适配器 | CPU离线运行，先单业务再增加背景流量 |
| 风险模型 | 截止时间交付概率 | 逻辑回归／梯度提升树起步 | 不以大模型训练为前提 |
| 任务回放 | 比较移动与补测策略 | 固定占据图、候选点和规划器 | 先二维／2.5D路径回放，无需完整机器人仿真栈 |

环境首选Linux或WSL2，先验证本机支持情况。Sionna RT、PHY／SYS、ns-3和视觉训练可以放在独立环境，通过带版本的文件接口交换，避免为一个包破坏其他环境。Sionna当前官方安装说明与旧教程可能不同，应以安装当日文档为准；RT在CPU上使用的Dr.Jit／LLVM依赖要单独核实。[Sionna官方安装说明](https://nvlabs.github.io/sionna/installation.html)

**没有可用GPU时**：继续做O轨道物理机制、P轨道感知误差、低分辨率参考场和ns-3；将V轨道中的完整3DGS训练列为后续条件。可以获得有价值的仿真结论，但不能把准确位姿＋CPU高斯集合包装成视觉SLAM系统。

**有兼容GPU时**：在核心RF机制通过后接入RGB-D高斯建图，测量训练／更新显存与延迟。显卡存在不等于全部依赖兼容，也不意味着整体系统满足实时要求。

## 3 首个场景：固定小问题，避免同时增加变量

下面参数用于第一轮工程调通，是拟定的可修改配置，不是已验证的最优选择。正式实验之前在DEV上固定。

| 项目 | 启动配置 |
|---|---|
| 场景 | 约8 m × 10 m × 3 m的室内空间，墙、门、桌子和一个可移动柜子 |
| 接入点 | 单个固定AP，高度约2.5 m；位置写入配置 |
| 接收端 | 高度约1 m；先固定朝向与天线模式，再研究旋转 |
| 无线配置 | 5 GHz、20 MHz、标称20 dBm；功率、天线、极化和增益口径固定 |
| 初始查询 | 可达区域粗网格／候选点，首轮间隔0.5–1 m；不是全空间毫米级采样 |
| 变化 | 柜子平移1 m；再分别测试旋转、移除、门开启 |
| 初始RF预算 | 先16个可达位置，每位置固定重复次数；扩展为8／16／32 |
| 无新增RF窗口 | 首轮取事件后2 s作为可复现窗口；根据观测周期和任务需求在DEV冻结 |
| 首个业务 | 单个UDP流，1200字节载荷、10包／秒、100 ms交付截止时间；后续做阈值敏感性 |
| 网络配置 | 先固定单空间流与MCS，确认信道效应；再单独打开速率自适应 |
| 负载 | 从无竞争到低／中／高背景竞争；保持每次成对比较的流量过程一致 |

首个场景必须包含四个条件：环境不变、仅环境变化、仅负载变化、环境与负载都变化。第三个条件用于检验模型是否错误地把拥塞归因于物体移动。

固定发射功率不意味着全部通信条件固定。需要另行控制或记录接收朝向、干扰源、AP关联、业务包大小、速率控制、重传上限和队列策略。

## 4 数据流：先建立隔离接口

### 4.1 三种输入轨道

| 轨道 | 算法获得什么 | 可以得出什么结论 |
|---|---|---|
| O：机制 | 准确ID与物体位姿，声明的几何；材质主设置仍只给先验／标定 | 属性迁移和传播重算能否工作 |
| P：误差 | O轨道上预定义的位置、角度、ID、漏检和覆盖率误差 | 哪类感知误差最危险、策略是否稳健 |
| V：观测 | 模拟RGB-D、可用相机位姿、算法检测／关联结果 | 在模拟传感器观测下整条链路是否成立 |

V轨道第一步允许准确相机位姿，但不得同时给物体真值位姿。随后可单独加入相机位姿误差。相机定位和物体追踪的oracle条件需要分别标注。

### 4.2 参考世界与算法世界

建议未来实现以下目录；这是接口草案，不代表已经生成了程序或数据。

```text
experiment_project/
  configs/              # 冻结配置、种子、版本、预算和划分
  reference_private/    # 真值几何、材质、脚本、RF和网络标签；算法进程不可读
  observations/         # RGB-D、可用位姿、初始RF和获准在线数据
  model_state/          # 实例高斯、RF代理、后验、依赖索引与版本
  predictions/          # 按决策时刻提交的预测与动作
  evaluations/          # 独立评分器输出
  src/                  # 渲染、RF、网络适配、模型、策略、评分模块
  reports/              # 每阶段结果与失败案例
```

每条观测至少包含：`event_id`、`timestamp_observed`、`timestamp_available`、坐标系、单位、配置ID、来源和是否oracle。预测至少包含：`issued_at`、`query_time`、地图版本、有效期、使用到的最新观测时刻。

尽可能通过独立进程／白名单文件接口把真值与算法隔离，而不只靠代码注释。评分器可以读取隐藏探针，预测器不能读取。正式测试的当前几何真值、材质、未来队列和查询点信道值不得出现在模型特征中。

### 4.3 信道与网络仿真的连接

先离线生成参考信道轨迹，再由ns-3按统一时间读取。适配器是一个需要实现并验证的模块，不是装好两个软件就自动完成。

1. 对AP、机器人及背景竞争节点的相关链路生成所需方向的增益轨迹；不能只更新AP—机器人链路，却让竞争节点的感知和干扰关系停留在旧环境。
2. 明确输入是线性功率增益还是dB损耗，规定发射功率及天线方向图在何处计入。已经包含总路径损耗时，不再叠加一次自由空间损耗。
3. 传播延迟与传播损耗分别处理。ns-3的`MatrixPropagationLossModel`按节点对存损耗，不能假定它会自动理解动态网格或物体位姿；需自定义模型或按仿真时间显式更新。[ns-3传播模型说明](https://www.nsnam.org/docs/models/html/propagation.html)
4. 初版用固定配置下的标量平均增益驱动PHY，属于窄化后的网络模型；不据此声称完整模拟频率选择性、MIMO或瞬时相干多径。
5. 背景竞争、队列、重传和速率控制由分组仿真产生。首轮使用简单Wi-Fi设置验证映射，再按研究问题增加干扰建模。[ns-3 Wi-Fi模型说明](https://www.nsnam.org/docs/models/html/wifi.html)
6. 物体越过遮挡边界时不能用粗时间线性插值制造虚假的平滑变化。比较事件断点插值和更细采样；冻结时间步长前做收敛检查。
7. RF参考生成的离线耗时、算法在线更新耗时与仿真时钟分别报告。算法算完之前继续用旧地图，不能让新预测在事件发生时立即生效。

初始低／中／高负载可按无变化场景的预标定可服务流量设置，标定规则对所有方法一致。预测器只读取决策时已观测的上下文；实际未来负载和服务器队列作为oracle上限另报。

## 7 核心方法的实现顺序

### 7.1 表示与迁移

先实现实例局部坐标与世界坐标转换；再增加RF部件属性和版本。对旋转物体，同时旋转几何和方向输入。测试刚体来回变换后几何是否一致、移动后旧位置是否清空、删除物体后穿透或反射关系是否正确失效。

初版保持物体几何固定，只从初始RF拟合少量有效参数。避免同时优化相机、形状、材质、厚度和高维神经网络。参数有多解时保存预测分布或等价解范围；不得把拟合成功称为材质识别成功。

### 7.2 更新范围

先实现全量重算作为正确性参考，再做依赖索引加速。索引必须包含旧传播失效和新路径发现。比较加速版与全量版在所有查询点上的差异，尤其检查远处被新增反射影响的区域。

“移动物体附近”的欧氏半径只可作为对照启发式，不能假定电磁影响局限在该半径。加速失败时触发全量回退并计入平均与P95成本。

### 7.3 不确定性

P轨道从单一误差来源开始：位置偏差→角度偏差→材质误判→ID混淆→漏检／未知表面→组合误差。误差级别在开发阶段设定，正式测试冻结，并报告随误差程度变化的曲线。

先比较三个简单方案：固定方差、校准残差区间、有限多假设。后者有独立收益再增加复杂后验。模型集成数量也属于计算预算，不允许用无限个假设换取无成本的高准确率。

材质先验至少比较统一材质、类别硬标签、类别概率、初始RF校准后的概率。无法识别的表面保留unknown，不以语义标签伪造确定材料。

### 7.4 补测策略

每个决策时刻输出动作和预测，动作执行完成后才能返回新测量。预计测量值从当前后验抽样；不能先查所有候选点真值再选“最有用”的点。

预算先取0／2／5／10个位置批次。每位置包数和等待时长固定，移动成本单列；随后允许适应性批次大小时，必须按总包数和总时间重新公平比较。

### 7.5 延迟预测

建立数据报级记录：发送时刻、到达时刻或未交付状态、截止时间、决策时刻的地图版本和可见上下文。主要训练目标是“是否在截止时间前交付”的二元概率，可用交叉熵训练并用Brier分数、校准与任务违约率评估。

成功报文的分位数回归仅作条件统计；未到达报文不得静默删除。仿真结束前尚无足够观察窗口的报文要延长追踪或标为右删失，不能直接当成丢包。该处理与单向延迟定义一致。[RFC 7679](https://www.rfc-editor.org/rfc/rfc7679.html)

固定UDP之后，再增加定长文件／图像传输完成时间。它需要独立的数据集、传输协议和截止时间，不能沿用UDP小包标签假装验证了远程VLM上传。

## 8 实验矩阵：分层扩展，避免组合爆炸

### 8.1 开发与确认数据

探索阶段6个布局：3 TRAIN、1 CAL、2 DEV。正式确认另生成12个布局：6 TRAIN、2 CAL、4 TEST。所有探索数据都视为开发数据；同底层布局的材质、位姿、负载和时间变体放在同一划分。

这些数量是起始工程预算，不能保证统计充分。先用DEV估计事件间差异和运行成本，必要时在看TEST之前调整正式规模。4个测试布局只能支持有限范围结论；不要用数百万包替代足够多的独立场景。

另设未见物体形状／材质组合测试，不与“仅在熟悉物体上换位姿”混报。程序化生成器的训练与测试差异也要记录，避免所有房间只是同一模板的微扰。

### 8.2 必做主矩阵

| 组 | 变化维度 | 固定其他条件 | 回答的问题 |
|---|---|---|---|
| M1 | 不变／平移／旋转／移除／门开启 | O轨道、固定材料假设与RF预算 | 基本更新是否正确 |
| M2 | 初始RF位置数8／16／32 | 选定事件、相同测量位置集合规则 | 初始数据效率与参数可辨识性 |
| M3 | 单一感知误差到组合误差 | P轨道、固定网络 | 预测何时不可信 |
| M4 | 补测位置批次0／2／5／10 | 同候选、相同噪声、同成本口径 | 决策采样是否胜过简单策略 |
| M5 | O／P／V及同观测网格／高斯 | 相同场景和允许信息 | 感知落差与表示收益 |
| M6 | 环境变化×负载变化四条件 | 固定业务与网络配置 | 地图对交付风险有多少独立解释力 |
| M7 | 固定任务下的通信代价方案 | 同目标、规划器、碰撞约束 | 风险地图是否改善任务 |

不要一开始对所有因素做全笛卡尔积。先逐组消融，找到问题后只在正式冻结前修改设计。最终主结论应来自预先指定的主矩阵，附加压力测试单列。

### 8.3 最小基线集合

1. 冻结的变化前CKM。
2. 使用相同估计几何、统一有效材料的物理重算。
3. 使用相同估计几何和初始数据的物体属性迁移方法，尽可能复现RFScape；若只是概念近似，命名为“object-transfer baseline”，不冒充官方结果。
4. 同观测点云／平面／网格与实例高斯方案。
5. 固定方差／残差校准与所提不确定性方法。
6. 同预算随机、均匀、最大方差、变化附近启发式与决策采样。
7. 延迟任务中的位置-only、网络-only、冻结CKM、动态CKM、动态CKM＋不确定性。
8. 准确物体位姿、准确材料、当前信道分别提供的oracle上限。

RFScape、URF-GS、CORF-GS、GS-CG等的完整适配按代码与资源可行性安排，但至少需要一个强物体迁移基线；只与过时地图比较不足以支持方法贡献。已发表方法的复现差异、预训练数据和未实现部分必须公开。

## 9 验收关卡与止损条件

以下是预先规划的工程／科学验收原则。数值容差、风险阈值和成本权重在DEV／CAL确定、正式TEST前冻结，不在看结果后选择。

| 关卡 | 通过条件 | 未通过时的处理 |
|---|---|---|
| G0：数据正确 | 无真值越权输入；单位和坐标自洽；相同配置可重复；隐藏标签不能影响预测 | 停止扩展功能，先修数据链路 |
| G1：物理与参考正确 | 自由空间等受控情形与解析预期一致；参考计算精度／采样尺度收敛；增密不改变物理代理含义 | 降低模型复杂度，排除数值假象 |
| G2：核心增量 | 同信息物体级强基线上，在预选主指标和成本约束下有稳定配对增益 | 取消“迁移本身创新”；转向明确的误差／风险问题 |
| G3：风险可用 | 高风险错误可被识别，且校准后比简单残差方案更有用 | 采用简单方案或重建误差来源模型 |
| G4：采样有价值 | 相同样本、时间、可达性和距离约束下，决策策略优于强采样对照 | 删除复杂主动策略，不靠新增预算制造收益 |
| G5：高斯有价值 | 同观测条件下至少在精度、视觉复用、更新延迟或资源中体现可解释优势 | 从主标题删除高斯；保留最有效地图表示 |
| G6：时延有价值 | 动态CKM在同网络上下文下改善未见位置的交付概率与校准 | 将延迟降为受限应用或移出首篇主线 |
| G7：闭环有价值 | 同规划器任务失败／超时减少，且额外移动与等待代价可接受 | 回到预测研究，不夸大机器人收益 |

方法间按布局和事件配对，报告效应量与不确定区间。随机种子只估计算法／网络随机性；像素、数据包和高斯不是独立场景。少量布局下的区间也不代表广泛泛化保证。

## 10 性能与成本账本

先测一个小场景，再估算扩展成本，不在未测硬件上承诺FPS。

| 项目 | 记录内容 |
|---|---|
| 离线参考 | 场景数、状态快照、查询点、路径阶数、单次与总耗时 |
| 初始建图／训练 | 帧数、分辨率、高斯数、迭代数、峰值内存／显存 |
| 在线更新 | 事件检测等待、关联、变换、RF代理、路径搜索、风险预测的分项与端到端P50／P95 |
| 在线负载 | 查询点数、多假设数、事件率、队列积压、版本落后时间 |
| 采样成本 | 位置批次、包数、等待、距离与动作执行时间 |
| 网络仿真 | 流数、包数、仿真时长、CPU墙钟时间和种子数 |
| 存储 | 图像、深度、几何、参考场、模型和分组日志分别占用 |

离线成本可用“场景状态数×每状态基准耗时”先估，再用扩展小批量验证非线性增长。发现预算过大时先减候选点与事件组合，保留严格划分和强基线；不要删除失败条件来降低成本。

参考模拟器能离线慢算，实际预测器若要进入机器人闭环则需要满足明确期限。分别报告“离线可完成”“能跟上输入速率”“满足任务截止时间”，不要混为实时。

## 11 论文证据与最终产物

建议最终至少包含以下图表，全部由真实运行日志产生：

1. 方法架构与信息边界图。
2. 环境变化前后，参考、冻结、更新地图及误差的并排图。
3. 位姿／材质／ID误差下的性能退化与风险识别曲线。
4. 测量预算—预测误差—任务失败的关系，附时间和移动成本。
5. 相同观测下，高斯与网格／平面代理的精度—时间—内存比较。
6. 环境与负载四条件的交付校准、超时率及网络-only对照。
7. 任务路径、违约率、总耗时和代表性失败案例。

每个阶段保留配置、代码版本、数据划分哈希、原始指标、人工干预记录和失败样例。若正式TEST发现需修改核心方法，新一轮测试应更换未使用确认数据，或明确改为探索性分析。

最终可以形成两种范围清楚的成果：

- 核心成立、视觉或网络扩展尚不充分：一项关于部分观测下动态信道更新与预算补测的仿真研究。
- 核心、V轨道、时延与任务验证均成立：一项面向通信可靠性的实例地图与风险决策系统研究。

这两个目标都不以购买机器人为前提。真实环境验证可在未来单独规划，当前仿真结论不提前写成真实机器人结论。
