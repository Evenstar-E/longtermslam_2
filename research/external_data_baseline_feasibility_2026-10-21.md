# 外部真实数据与强方法可运行性验证（2026-10-21）

本轮取得并运行了**一组真实跨次RGB-D样本**，把后续实验从程序化场景推进到实际相机数据。结果同时表明：首个PnP前端失稳，可以由普通RGB-D刚体配准明显改善，不能把这个失败直接认定为新算法空间。Khronos已核对到可适配本机ROS Noetic的官方版本，并生成17项直接依赖的固定提交清单；完整编译和时序建图仍未执行。

这是“真实输入、普通基线和强方法复现条件”的验收报告。候选研究方向仍是**跨次巡检中正确关联、可比较、可用的视觉证据**；本轮没有确立新的感知、规划或控制算法贡献。

## 1. 实际取得了什么

选用[OpenLORIS-Scene官方数据](https://lifelong-robotic-vision.github.io/dataset/scene.html)，其用途包含真实机器人多次采集下的场景变化和长期定位。官方说明提供颜色对齐深度、相机标定，并规定uint16深度乘0.001转换为米。本次遵循[官方许可与下载页](https://github.com/lifelong-robotic-vision/OpenLORIS-Scene/blob/master/download.md)指向的作者Hugging Face仓库，未使用第三方重新标注的数据。

|---|---|---|
| 序列 | office1-2 | office1-7 |
| RGB时间戳，秒 | 1560000137.216960 | 1560244976.164564 |
| 对齐深度时间戳，秒 | 1560000137.216955 | 1560244976.164557 |
| RGB／深度时间戳差 | 约5.01微秒 | 约6.91微秒 |
| 原始尺寸 | 848×480 | 848×480 |
| 有效深度比例 | 98.79% | 98.87% |
| 有效深度中位数 | 2.455米 | 2.668米 |
| 文件 | 原始RGB、对齐深度、sensors.yaml、trans_matrix.yaml | 同左 |

两次采集间隔244838.95秒，即**2.8338天**。官方参考轨迹对应的机器人位置相差约0.194米、姿态相差约9.60度。这些同步数字来自文件时间戳，不能解释成独立测得的硬件同步误差。

数据来源固定到Hugging Face版本 `cbc03108723d08322b23d0338680bffa9404cce9`。原始8个文件及SHA256见[采集记录](../data/external_feasibility_v1/raw_sample_v2/acquisition.json)。

原始数据位于 `data/external_feasibility_v1/raw_sample_v2/`。官方许可为CC BY-ND 4.0，本轮用于本地分析，没有发布派生数据集；数据许可与工具仓库MIT许可分别记录。

## 2. 如何选择，是否按成败挑样本

选择仅使用文件时间、官方参考轨迹和归档读取成本，没有运行待比较算法后筛选图像：

1. 同一次采集的RGB与对齐深度时间戳差不超过20毫秒。
2. 最近官方参考位姿时间支持不超过20毫秒。
3. 两次采集的机器人平移不超过0.5米、旋转不超过20度。
4. 限制压缩流前缀读取量，并在合格配对中选择读取成本较低的一组。

初查office1-1／office1-7在该读取范围内没有合格配对；随后检查office1-2／office1-7和office1-3／office1-7，前者最小读取成本更低。最终配对在运行普通基线前保存为[sample_plan.json](../data/external_feasibility_v1/sample_plan.json)，候选数、几何条件和其他候选均保留。

**它是方便检查的开发样本，不是随机抽样，也不是独立确认集。**官方位姿用于挑选重叠视角属于特权样本选择，不能包装成无人机自己找到复检视角。

为读取原始图像，先按HTTP Range解析10.6GB外层tar，再解析其中7z索引。首次py7zr预读量过大，触及预设传输预算；限制解压阶段的预读后复用缓存完成提取。失败记录和部分文件保留，没有覆盖。归档传输累计约0.44GiB，未下载完整10.6GB数据包。保存了范围与文件哈希，校验了选中文件的7z CRC，**未校验完整tar的SHA256**。

## 3. 标定与输入合同

这份相机文件的四个数实际为 \([f_x,c_x,f_y,c_y]\)，不是常见的 \([f_x,f_y,c_x,c_y]\)。本次解析得到：

$$
K=
\begin{bmatrix}
611.45099&0&433.20398\\
0&611.48572&249.47302\\
0&0&1
\end{bmatrix},\qquad
D_{\mathrm m}=0.001D_{\mathrm{uint16}}.
$$

两个序列的颜色相机内参一致，文件中的畸变系数为零；深度0作为无效观测处理。原始颜色PNG逐字节保留，深度换算为米制数组，未给真实图像添加合成缺陷。

普通估计函数只接收RGB-D、内参、历史ROI和参数。官方位姿与外参用于评价：

$$
T^w_{c,h}=T^w_{b,h}T^b_c,\qquad
T^w_{c,t}=T^w_{b,t}T^b_c,\qquad
T_{t\leftarrow h}^{\rm ref}=(T^w_{c,t})^{-1}T^w_{c,h}.
$$

这里使用最近时间的OptiTrack机器人参考位姿及原始相机外参，仍有测量、标定及时间近似误差；不能称为无误差真值。

历史ROI取前景显示器／推车区域 \([120,200,330,400]\)。它由研究者看过图像后、计算基线前标注；没有工业构件ID、物体实例身份或缺陷真值。ROI在SIFT配准时屏蔽。它用于输入和误差诊断，未构成正式巡检任务集。

## 4. 普通方法实跑结果

先原样使用首个程序化样例的SIFT／PnP和RGB-D检测代码、参数；再对保存的同一组44个SIFT候选匹配做事后诊断。未覆盖原始运行。

| 方法／诊断 | 结果 | 能说明什么 |
|---|---|---|
| 原SIFT＋EPNP-RANSAC＋LM | 44个候选，返回13个初始一致集索引；低于原门限15，拒绝输出位姿 | 现有前端在此对真实图像上未通过验收 |
| 原求解进一步核查 | 返回位姿上原一致集残差中位数约38.06像素，重新计算后无匹配低于2.5像素 | 返回的一致集索引不能直接当作最终有效内点；要检查几何退化和重求解后残差 |
| 同匹配AP3P，带／不带LM | 两种结果分别仍约0.55／0.97米、47.7／48.2度参考误差 | 简单更换PnP选项没有自动解决本例 |
| 普通3D／3D刚体RANSAC＋SVD | 44个可用3D对应中13个通过5厘米残差门限；内点残差中位数约2.49厘米 | 当前深度提供了可用几何约束 |
| 3D／3D结果对官方参考位姿 | 平移约6.29厘米，旋转约1.54度 | 一个可用的粗配准候选；不代表小缺陷ROI达到巡检精度 |

3D／3D方法使用已有的刚体最小二乘与RANSAC：从3个非退化对应求解 \(R,t\)，按米制3D残差找一致集，再用SVD重估：

$$
\min_{R\in SO(3),\,t}\ \sum_{i\in\mathcal I}
\left\|R\,D_h(u_i)K^{-1}\bar u_i+t
-D_t(v_i)K^{-1}\bar v_i\right\|_2^2.
$$

这属于普通既有方法。本次固定随机种子、2000次采样、5厘米3D残差门限，未用官方位姿筛选候选；参考位姿只在求解后评价。它是**看到原失败后的事后工程诊断**，未经独立确认。

两类求解的残差量纲、使用的几何约束和接受门限不同：原PnP最少15个内点、3D／3D诊断最少6个，因此不能直接拿接受／拒绝次数评价算法优劣。3D结果的参考误差比强行接受原错误位姿小，但不能由单例证明其普遍优势。

![普通RGB-D刚体配准实际使用的对应](../results/real_pair_rgbd_ransac_v1/matches.png)

原基线因配准失败输出“证据不足”；参考位姿诊断和3D／3D后接相同检测器都输出“变化”。由于没有物体变化标注，**没有计算准确率、召回率或巡检成功率**。目视可见场景布置不同，但“缺失／移动／遮挡／任务关联错误”仍需独立标注，不能用检测器输出替代真值。

最直接的研究判断是：这次确实遇到了真实图像匹配与几何问题，但现成RGB-D方法已能改善。新算法必要性仍未建立，也不应把课题改名成“这个PnP例子的修补”。

## 6. 为什么不能把Khronos接两张图就宣布公平比较

Khronos研究的是时序地图、对象和射线证据，双帧不能提供完整观测历史。官方真实样例还使用预先记录的语义和里程计；OpenLORIS当前提取物没有这些语义标签。正式比较必须明确：

- 同一段历史和当前轨迹、相同RGB-D与有效深度，不给某种方法额外的未来帧。
- 位姿由同一普通前端提供，或把“各自完整SLAM系统”作为另一种实验，避免混在一张排名表。
- 真实数据的预测语义、预录预测语义和真值语义分别标明；不能仅给强方法特权标签后再与弱方法比较，反之也不能删除强方法正常需要的输入。
- 对象级时序变化与局部巡检ROI是不同输出合同；要说明从地图输出任务证据的适配方式及精度限制。

本轮只核查了源码和输入要求，没有运行Khronos、POV-SLAM或新近时序方法，也没有用普通3D／3D基线代替它们宣称完成强方法对比。
