# 双期观测接口 v1：实现、开发数据与主线审查

日期：2026-10-22。状态：接口和开发数据已实现并运行；候选选择算法和七组策略对比尚未实现。不能将本轮轨迹当作研究效果实验。

## 1. 已执行的具体工作

新建 `comparative_evidence/`，与既有 cuboid/MILP 代码和结果分开：

- `scene.py`：通过凸多面体半空间与相机射线相交生成 RGB-D。8个资产包含旋转六棱柱、楔体、非凸 L 形支架；物体姿态不是轴对齐。非凸物体由多个凸部分组成，渲染最近表面。相同资产在两期保持形状，仅发生刚体平移。
- `interface.py`：`Episode` 管理已取回历史、当前已观察视角、位置、预算和事件；`components` 只从 RGB-D 提取颜色连通区域、相机坐标点和局部法向，不读取评价实例掩码、物体中心或真实相机姿态。
- `policy.py`：`execute_policy` 为后续所有策略提供同一 `PolicyPort`，只开放元数据、初始预览、已执行状态和合法动作。独立记录策略计算、API耗时、读取载荷及路程。
- 配置 `configs/comparative_evidence_interface_v1.json` 定义本轮接口开发；上一轮冻结研究协议保留未改写。

## 2. 策略到底能看到什么

| 时点/动作 | 可获得的信息 | 费用 |
|---|---|---|
| 开始 | 历史12帧的名义相机元数据、24×18缩略图和全图颜色均值；当前12个候选位置及可达边；共同误差模型 | 全部索引字节计入，每种方法一致 |
| 初始预览 | 当前视角0的RGB-D、名义位姿、观测连通区域 | 一帧载荷与一次模型化采集费用；各方法相同 |
| `retrieve_history(i)` | 被取回的历史帧RGB-D和观测区域 | 首次读取计载荷字节、IO/提取耗时，占历史预算 |
| `observe_current(i)` | 执行动作后该位置的当前RGB-D和区域 | 从当前位置沿离散图最短路径移动；首次观测计载荷和采集费用，占当前追加预算 |
| 结束 | 自动返回预览位置，记录返程 | 返程路程计入；不会凭空增加图像 |

每一帧用 `nuisance_group` 记录共同误差来源，同一帧的所有点受同一相机/深度扰动；共享误差条件下同一时期还共享一部分扰动。实际扰动影响名义相机和深度图，不只是声明一个误差条。实现为归一化扰动 `u=0.7*u_epoch+0.3*u_frame`，独立条件则只有 `u_frame`；分量范围[-1,1]，平移0.04m、旋转0.005rad、深度偏差0.015m。

原始载荷仅有 `rgb/depth/nominal_T`，真实实例掩码、形状、位移和扰动写在独立评价目录。API不读取该目录。返回对象是防御性副本；外部修改不能改写缓存。重复取回已缓存观测只返回旧证据，不会产生新的采集、移动或收费；若要回到旧视角重新拍摄，当前版本没有单独的重拍动作，后续算法不得假定缓存读取会更新场景。

数据流隔离适用于可信策略代码，不是抵御恶意Python文件访问或反射的操作系统沙箱。后续策略不能直接遍历载荷目录、访问闭包或调用渲染器。若需要外部不可信代理，再做进程/权限隔离，不把当前API测试称为安全证明。

历史实例没有直接传递物理资产ID；当前也没有。这里输出的是局部观测区域及其外观组。后续必须建立历史参考实体及其观测归属，再做当前关联；资产身份评分要明确参考命名/注册规则，不能临时把评价ID作为算法输入。当前接口没有因此获得设备编号识别能力。

## 3. 本轮实际运行

48个开发场景，16个因子单元各3个种子：历史视角范围窄/多样 × 独立/共享误差 × 唯一/重复外观 × 0/3个变位资产。

每场景实际生成12帧历史＋12帧当前，共 **1152帧RGB-D载荷**。存储约72.6MB，包括评价文件。历史范围窄时12个视角在前方小角域，多样时分布在一圈；当前候选视角始终为一圈。当前每帧有实际前景遮挡物。

分别执行(历史2/当前追加1)、(4/2)、(8/4)三档预算，初始预览另计且相同，得到 **144条完整动作轨迹**。动作序列是固定的接口练习，不能称为最近邻策略、覆盖策略或候选算法。没有变化F1、位移精度或论文增益比较。

生成和轨迹运行84.49秒；全部场景和轨迹保留，无剔除。确认集256个场景尚未生成，研究协议依然是设计冻结、未运行状态。

独立评价计数：48场景×8=384个资产在历史第0帧和当前预览都至少有12个像素；其中72个真实变位资产也全部达到该可见像素条件。因此本批遮挡是**部分表面遮挡**，没有展示全目标不可见、完全移除或重现的困难。像素数量达到门槛不等于检测、配对和位移估计已经正确。不能拿此计数证明感知覆盖率100%或当前预览足够完成任务。

## 4. 检查和发现的问题

7项单元测试通过，覆盖射线交点/未命中、预算拒绝的状态原子性、缓存不重复收费、返回值不可污染内部状态、路径费用及返程、真值/未执行文件不被读取、相同种子传感器数组重放、统一策略入口。其中“移除真值文件和未执行视角文件后仍能完成其它合法动作”检查的是实际文件依赖，并非只检查字段名。

独立分析脚本遍历保存数据进行17144项校验：所有源/载荷哈希、RGB-D键和尺寸、有限正深度、真实与名义相机扰动关系、共同误差组、因子平衡、每步载荷费用、最短路径与返程、采集费用及完整轨迹计数全部一致。校验数不是实验样本数；不代替算法统计检验。接触表已人工视觉检查。

首次测试因系统临时目录子目录不可写而失败，改为工作区内已检查路径的临时目录后通过；这是运行环境工程问题。没有改评价规则或删除困难场景。

路径只验证离散相机边：用包围全部资产/遮挡的球体和0.35m余量，对真实及名义相机弦段检查，所有边都在包围球外。它保证此模拟几何中可行，不是现实无人机动力学或安全验证。元数据给出允许的边，不向策略提供真实地图来预测可见性。

## 5. 主线审查

| 项目 | 判断 |
|---|---|
| 是否推进主线 | 是，搭建了证据/动作会改变可用输入的可交互环境，后续能真正比较“选什么证据”，而不只比较固定点集上的后端 |
| 本轮新增的问题 | 部分遮挡不等于完全不可见；颜色分割仍理想；历史参考身份的注册/评分规则需要明确；可达性仅为离散几何 |
| 工程问题 | API访问约束、费用、路径、载荷来源、重放、基准身份协议；本轮已有可验证实现，不能包装为论文创新 |
| 可研究的问题 | 有限预算下，多个关联/相机解释与共享误差是否要求不同于通用任务信息增益的成对证据选择；尚无候选效果数据 |
| 论文创新收益 | 本轮未建立新算法收益。它是执行已冻结算法实验的必要基础，不是再次证明研究问题必要性 |
| 下一步 | 使用这48个开发场景实现共同表面/参考实体表示、强任务信息策略及候选；停止新增无关接口或扩增理想场景来代替算法实验 |

下一轮实现时先固定参考命名：实体身份来自历史观测形成的参考实例，评价器只负责把参考实例对应到物理资产以评分；若采用人工注册/已知历史轨迹，应明确为共同输入，并保留无此信息的边界。不能让真值实例掩码进入当前关联。

候选与所有对照必须共用可用观测、参考实体、关联候选和变化/位移估计后端。先在开发集完善实现并记录失败，策略冻结后才生成256个确认场景。不能因为图像接口已通过就跳过强对照或宣布高创新性。
