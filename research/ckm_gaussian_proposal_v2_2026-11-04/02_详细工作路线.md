# 工作路线 V2：先验证任务价值，再建设动态实例CKM

**日期：2026-11-04｜按单人、仅电脑、先仿真规划｜16周是开发排期，不是性能或发表承诺。**

对应：[研究方案](01_研究方案.md)、[平台选型与证据边界](03_平台选型与证据边界.md)。本文件是实施计划，其中程序、数据、图表和检查项均为待完成工作，不能据此理解为已安装或已运行。

## 1 开发顺序与阶段目标

**最先做一个房间、一个可移动柜子、一个AP、一个待核验目标和几个观察点。**

先让网络执行器正确控制图像何时能够被服务器读取，再证明视觉质量与交付风险之间存在合理冲突。接下来实现实例CKM和强基线，然后加入不确定性、有限补测与真实合成视觉，最后开展独立布局测试。

~~~mermaid
flowchart LR
    A[第1—2周：协议门控与任务可行性] --> B[第3—4周：参考RF与实例迁移基线]
    B --> C[第5—6周：不确定性与失效识别]
    C --> D[第7—8周：预算补测与表示比较]
    D --> E[第9—10周：合成视觉与固定验证器]
    E --> F[第11—12周：通信模型复核]
    F --> G[第13—14周：任务闭环]
    G --> H[第15—16周：冻结测试与论文证据]
~~~

每个阶段都有可保留产物；上游失败时暂停依赖它的后续工作。16周不足时优先保住“实例更新—可信度—任务增益”的证据，削减3DGS扩展、完整导航和行人场景。

### 1.1 SuperMap尚无可用官方源码时怎么启动

**先完整复现SuperMap不是本路线的前置任务。** 2026-11-04检查官方仓库默认分支，目前只有README和doc可见，运行示例所需的源码未公开；因此不安排依赖该源码的安装步骤。[官方仓库](https://github.com/superxslam/SuperMap)

具体按以下顺序补上实例输入：

| 层级 | 如何得到实例状态 | 能验证什么 |
|---|---|---|
| O机制实验 | 从仿真取对象ID、位姿和形状；材料真值单列oracle | CKM更新与决策机制，不能证明机器人识别变化 |
| P鲁棒性实验 | 在O输入上施加预定义漏检、误关联、位姿误差和到达延迟 | 对假定感知误差的敏感性 |
| V视觉实验 | RGB-D＋相机位姿→检测／掩码→实例点云→跨帧匹配→变化状态 | 实际合成图像下的感知与CKM链路 |
| 可选官方对照 | 将来有可用源码后固定版本，适配同一实例接口 | 才能评价与官方实现的一致性和差异 |

V阶段只建设CKM需要的最小功能：实例ID、局部表面、位姿估计、存在／遮挡状态、更新时间与置信度。先以点云／体素保存，不要求3DGS、完整场景图、语言导航或重新实现SuperOdometry。

可以依据论文第IV-B节和补充材料Algorithm 1独立实现3D投影辅助关联及几何／语义一致性维护，但需要自行决定并公开原文未充分确定的参数、缓存、重激活和工程细节。应命名为“受SuperMap启发的实例地图基线”；不能将其结果写成SuperMap官方复现。[论文方法与补充算法](https://arxiv.org/html/2608.22896)

关键验收场景：相机移动但物体不动时ID稳定；短时遮挡不误删；确认自由空间后清理旧位置；两个同类物体不过度合并；未知物体保留新对象假设。物体质心变化不等于完整6DoF位姿恢复：柜子转动等RF任务还需局部点云配准或单独的姿态估计，并记录对称物体的姿态歧义。

如果V阶段工程量超出预计，应延长或收窄视觉集成阶段，优先交付O/P范围内的CKM研究；不能用仿真真值替代视觉输入后继续声称端到端系统已验证。

## 2 先决定电脑能承担哪一层

第1天记录操作系统、CPU、内存、GPU／显存、驱动、可用磁盘和已有Python环境。硬件未核实前，不假定能实时运行Isaac Sim、3DGS、Sionna和VLM。

| 资源情况 | 可立即推进的路线 | 暂缓的主张 |
|---|---|---|
| 无兼容GPU，或显存／内存不足 | CPU网络原型、简单几何、低分辨率参考RF、O/P误差轨道、离线观察回放 | 实时Isaac视觉闭环、完整3DGS系统 |
| 能运行Isaac但无法同时承载全部模块 | 分进程或分阶段生成视觉／RF数据；在线只运行轻量策略 | 各模块同时实时运行 |
| 能稳定运行完整小场景 | 单环境、低分辨率、有限对象，逐步加负载 | 大规模并行、复杂多楼层 |

允许离线生成世界数据与固定验证器结果，但必须由隔离执行器按采集、传输和服务时刻释放，不能让策略直接读取未来缓存。离线回放验证的是算法逻辑与模拟任务收益；实际运行速度单独测量。

只选择一套满足目标能力的版本组合。Isaac-Net、Isaac Sim、Isaac Lab、PyTorch、Sionna RT与ns-3分别记录版本及代码提交。不要将不同年代扩展的依赖强行装进同一个环境，也不要因为项目支持CPU就推断完整视觉系统也支持。

## 4 16周详细排期

### 阶段A：第1—2周，证明任务与执行链可行

**输入：**简单几何、固定AP、图像字节配置、候选观察点。先用模型桩提供服务时间，不加载完整导航系统。

具体工作：

1. 完成首周任务；明确网络后端是否能表达固定负载、动态链路、丢包、超时与请求大小。
2. 实现请求状态机：等待发送→传输／重试→完整到达→排队→推理→返回→有效结果，另有失败／超时状态。
3. 明确返回路径。若低成本后端只有Wi-Fi上行，初版可用已声明的固定有线返回延迟；这属于受限模型，后续用ns-3无线下行检查，不能称为完整双向Wi-Fi。
4. 扫描几种合理图像大小、负载和任务截止时间，找出链路、视觉和计算分别主导的区域。
5. 固定主实验的可行条件范围，并保留“几乎不受通信影响”的负对照，避免只挑有利条件。

**交付：**最小事件执行器、请求时间线、任务条件扫描、平台选择记录。

**进入下一阶段：**错误信息不会提前进入验证器；丢失必要图像会阻止请求完成；存在可解释的动作取舍。暂不要求某个新算法优于基线。

**停止／调整：**如果图像都能在极短时间传完、或服务时间完全主导，先调整为现实可辩护的任务条件；仍无作用则将应用降为次要展示，继续地图机制研究。

### 阶段B：第3—4周，参考RF、信息隔离与强基线

**输入：**开发布局及其事件脚本，初始RF采样预算，O轨道实例状态。

具体工作：

1. 参考世界使用完整几何与材料；算法侧只收到公开输入契约中的字段。真值与估计地图存放在不同模块。
2. 检查自由空间、单墙／单门与单反射体的小例子；验证功率、dB／线性变换、坐标系和天线高度。
3. 用足够采样的Sionna快照生成参考增益；记录射线数／交互深度变化下的收敛误差。不能将采样噪声误判为环境变化。
4. 实现冻结地图、同观测几何全量重算、确定性实例RF迁移基线；先让物体平移／旋转的局部坐标处理正确。
5. 对新物体、消失对象和门部件建立明确状态转移。参考世界使用完整材料不代表算法也可以知道。
6. 研究算法端先用低阶传播代理，例如直达、声明的透射近似与少量反射，并与更丰富参考模型形成失配。

**交付：**基础数据格式、参考地图、3个最低必要基线、事件前后误差图。

**进入下一阶段：**几何变化确实导致超出参考数值波动的信道差异；所有基线看到同一份观测；无变化条件下不会持续虚假更新。

**停止／调整：**如果简单迁移已准确覆盖所有事件，应主动增加部分观测／新对象等合理难例，而不是人为削弱基线。

### 阶段C：第5—6周，联合假设、校准与失效识别

**输入：**P轨道中预定义的位姿、身份与材料误差；独立CAL集。

具体工作：

1. 实现少量联合场景假设，先只对一到两个变化对象展开，记录假设数与运算成本。
2. 完成视觉事件更新、RF测量到达后的权重更新，以及未知对象／低有效样本数时的回退。
3. 先全查询重算，再做局部失效和候选新路径搜索；比较漏更新与节省的查询数。
4. 使用CAL残差校准区间；比较固定误差带、简单集成和本方法。测试集不能参与区间调整。
5. 加入误关联和不可见对象离开，检查系统是否有机会输出未知，防止置信度只会上升。

**交付：**覆盖率—区间宽度图、误差—计算预算图、失效案例、零新RF窗口结果。

**进入下一阶段：**在匹配覆盖率或匹配宽度的比较下有优势，或者能清楚定位方法有效的条件。区间无限放宽不能算改进。

**停止／调整：**若性能完全依赖正确ID或准确材质，先修正假设建模，并收窄结论；不直接进入完整导航。

### 阶段D：第7—8周，预算补测与高斯表示决策

**输入：**固定候选任务动作及其开发集视觉质量估计；阶段C的不确定性模型。

具体工作：

1. 实现随机、均匀、最大方差、变化区域和任务VOI补测；统一探测批次及总成本。
2. 从模型预测抽取假想测量，检查VOI计算不读取候选点隐藏真值；真正执行探测才得到观测。
3. 增加总移动／时间预算，防止方法通过远距离高成本补测获取优势。
4. 在冻结候选动作集上评价决策后悔值与排名改变；这只是任务代理结果，后面需真实核验确认。
5. 比较实例平面／网格与3DGS。先使用同一批有限RGB-D建立地图，再比较表面质量、更新成本和无线误差；硬件不支持时本项顺延，不阻断CKM主线。

**交付：**补测成本—决策损失曲线、表示对照、方法范围决定。

**进入下一阶段：**补测收益不是通过增加包数、等待或移动距离换来的未计费优势。若3DGS没有收益，在后续主实验采用较简单表示，同时保留消融结论。

**停止／调整：**如果VOI计算成本超过补测收益，保留低成本近似或删除这项贡献，不引入更大策略网络掩盖问题。

### 阶段E：第9—10周，实际合成视觉与固定目标验证器

**输入：**Isaac可运行小场景，或能够明确说明来源的合成RGB-D回放。

具体工作：

1. 固定感知模型，生成实际实例掩码／几何／关联结果；记录已知相机位姿与其他oracle。
2. 从几何观测提取RF代理表面，运行与O/P相同的地图接口，分别报告感知错误和传播错误。
3. 选择本机能运行的固定验证器；锁定模型、提示词、解码、图像尺寸和版本，不做测试集调参。
4. 建立真实目标／相似干扰物、多角度和遮挡的图像集。测单图与多图错误率，不能假设增加视图总是更好。
5. 记录图像实际编码字节数与服务时间；缓存只用于减少重复计算，策略只能在允许时间看到结果。
6. 在TRAIN/CAL建立视觉质量到正确率的映射；对未来视点使用地图推断特征，禁止提前读取该视点图像或标签。

**交付：**V轨道地图评价、验证器错误分类、服务时间轨迹、视觉质量校准。

**进入下一阶段：**实际观测中的关键错误已被模型覆盖；目标验证不是完美oracle；输入／缓存访问规则可审计。

**停止／调整：**若只有O/P成立而V失败，优先完善实例关联，或者将论文范围限定为给定实例状态的动态CKM，不宣称端到端视觉系统。

### 阶段F：第11—12周，网络保真度与风险模型

**输入：**固定请求语义、参考信道轨迹、实际图像字节数和服务时间轨迹。

具体工作：

1. 在低成本后端拟合／校准请求完成风险；比较位置、网络历史及CKM各自提供的信息。
2. 用ns-3 Wi-Fi复核代表性链路好／差、低／高负载和遮挡突变条件。先检查单链路，再加入背景竞争。
3. 注入所有相关链路，包括AP—机器人及竞争节点之间的链路；只改目标链路不足以复现隐藏节点与载波侦听。
4. 核对损耗是否被重复计算，重传、速率控制、包长、队列和返回协议是否一致。若无法严格匹配，记录差异并做敏感性分析。
5. 比较交付率、截止违约、尾时延和候选动作排序；预先定义可接受误差与排序稳定性要求。
6. 在固定模型之外改变服务负载，检查“CKM预测时延”的收益是否仅由负载相关性造成。

**交付：**两后端差异表、风险校准图、可支持结论的条件范围。

**进入下一阶段：**关键策略排序在独立后端中没有无法解释的反转，或已明确改用更可靠后端作为主评测。不能用测试后端的TEST数据回头调快模型。

**停止／调整：**若差异显著，缩减主实验到可靠条件；已有Isaac-Net仓库基准不能替代本任务的检查。

### 阶段G：第13—14周，闭环动作选择

**输入：**固定验证器、动态CKM、通信风险模型与可达观察点。

具体工作：

1. 先固定图像数量与编码，只选择观察点／发送时机；再开启已有图像子集选择。
2. 接入任务VOI补测，计入探测造成的排队与任务时间；最多一个在途核验请求。
3. 对比视觉优先、通信优先、固定发送、网络历史自适应、冻结地图、本方法。
4. 执行同字节数、同视图数、无不确定性、无补测和无动态地图消融。
5. 最后接入固定局部导航器；若时间允许做单层完整导航展示，但不改变核心评测定义。

**交付：**及时正确验证率、错误接受率、成本和任务时间的权衡图，典型成功／失败轨迹。

**进入下一阶段：**在DEV中有稳定、可解释的改善，或已形成清楚的失败边界。开始正式测试前冻结版本与主指标。

**停止／调整：**如果地图RMSE改善却没有任务收益，如实报告，检查决策相关区域和基线是否已经足够；不能只展示最好的一条视频。

### 阶段H：第15—16周，独立测试与论文证据

1. 建立正式数据清单：6 TRAIN、2 CAL、4 TEST基础布局，场景家族与资产变体不跨集合。
2. 用正式TRAIN重新拟合、CAL校准；开发集已用于设计，不并入最终TEST。
3. 冻结方法、阈值、候选点规则、协议、事件脚本和统计脚本后执行TEST。
4. 按布局／事件配对汇总置信区间，分别报告理想输入、受控误差与实际视觉。
5. 如果独立布局过少导致区间宽，增加新布局；不要把包数当独立样本量。
6. 整理完整配置、运行日志、失败案例、复现说明和方法边界，依据结果改写论文贡献。

**交付：**可复核的结果包、论文图表、方法与局限初稿。发现缺陷后允许修复，但必须标记原测试已经参与开发，并增加新的确认测试；不能把反复调参后的结果继续称作一次性盲测。

网络世界与算法预测使用不同对象和调用路径。接口测试要能发现“把估计信道接入真实通信结果”的误连，而不只检查数组形状。

## 6 时钟、反馈与成本：必须提前固定的规则

1. **使用统一仿真时间。** 物理、RF、网络和服务可以不同频率运行，但事件都有发生时间与可用时间；仅按时间顺序释放信息。
2. **区分模拟任务时长与电脑运行耗时。** 离线Sionna运行慢不等于通信延迟；在线方法实际算得慢也不能免费。分别报告仿真加速比，并为实际在线计算设置实测或明确建模的处理时间。
3. **保留数据年龄。** 图像采集时间、地图更新时间和结果返回时间分别记录；接收结果时检验对象ID／版本。
4. **不得偷看服务端状态。** 真实不可见的服务器队列只用于生成结果；算法若使用其估计值，写清来自什么遥测以及何时到达。
5. **分别记录主动与被动RF信息。** 普通上传产生的反馈不是免费、也不是变化前信息；严格零新RF实验与部署实验分开。
6. **统一随机条件，但允许内生状态变化。** 同一配对试验共用外生事件与背景流量生成规则；策略改变自身发包后，队列不能被强制固定为基线轨迹。
7. **预算不只数测量次数。** 记录图像、探测、控制、确认及重试字节；记录额外移动、等待和本地／边缘计算。
8. **处理停止时未完成请求。** 已超deadline记失败；尚未到deadline而仿真停止的请求记删失，或延长到结局可判定。

每次运行至少保存：

~~~text
run_id, split, layout_id, event_id, asset_family, seed
world_version, method_version, network_version, radio_config
sim_time, event_time, captured_at, available_at
instance_id, instance_version, map_version, prediction_valid_until
request_id, image_ids, bytes_submitted, bytes_delivered, retry_bytes
deadline, queue_enter, upload_complete, service_start, service_end, return_time
predicted_gain, predicted_interval, predicted_success, selected_action
probe_cost, move_distance, local_compute_time, outcome, failure_reason
~~~

隐藏真值字段单独存放或通过权限／模块隔离提供给评价器，不能让训练数据加载器默认把它们全部拼成算法特征。

## 7 必要验证项：围绕会改变结论的错误

| 检查 | 预期性质 | 防止的问题 |
|---|---|---|
| 坐标和旋转 | 同一物体换坐标表达后传播结果一致；世界实际旋转按天线／场景改变 | 坐标错位伪装成物理变化 |
| 功率计量 | 线性聚合再转dB；损耗与天线增益只计一次 | 数值错误制造信道改善 |
| 世界／预测分离 | 故意改坏预测CKM不应直接改世界信道，只能通过动作间接影响 | 自己预测、自己当真值评分 |
| 时间门控 | 故意延迟交付，验证器不得提前看图 | 延迟仅存在于日志 |
| 完整性 | 缺少必需分包时不进入推理；重复包不重复计成功 | 多视图数量与传输成本不真实 |
| 未知／越界 | 不在地图内或预测过期有显式处理 | 边界插值产生假置信 |
| 地图更新 | 新反射路径、远处遮挡、新对象被覆盖或触发回退 | 只更新旧路径附近 |
| 预算 | 多次探测、重试、等待和绕路均被计费 | 以隐藏成本换效果 |
| 数据隔离 | TEST资产与布局不进入训练／校准；未来缓存不可见 | 信息泄漏 |
| 基线公平 | 相同观测、验证器、候选点和初始预算 | 模型大小或输入差异冒充算法贡献 |

这些是实施阶段应完成的验证；本次文档更新只检查文档一致性，未执行这些实验。

## 8 最低实验集合与图表计划

优先按问题分批，不一开始对所有因素做完整笛卡尔积。

| 实验 | 最低控制因素 | 计划图表 | 支持的论点 |
|---|---|---|---|
| E0：任务可行性 | 链路×图像大小×负载×deadline | 动作冲突区域图 | 应用值得研究的条件 |
| E1：变化更新 | 搬移／旋转／开门／新对象，0新RF | 事件后增益误差与更新时间 | 视觉事件能带来有效地图变化 |
| E2：不确定性 | 位姿／身份／材料误差 | 覆盖率—宽度与失效识别 | H1 |
| E3：预算补测 | 0／2／5／10批次，总成本匹配 | 成本—决策损失曲线 | H2 |
| E4：表示必要性 | 同观测平面／网格／3DGS | 精度—内存—更新代价 | 高斯是否值得保留 |
| E5：网络模型 | 快速后端与ns-3，条件匹配 | 违约率和排序差异 | 后端依赖边界 |
| E6：目标核验 | 同验证器、同字节／视图预算 | 及时正确率与错误接受率 | H3 |
| E7：失败边界 | 未见布局、未知物体、重负载、快速变化 | 分组结果与案例 | 结论适用范围 |

配图优先保留系统图、事件示例、误差恢复曲线、校准图、成本权衡和任务结果。每幅图回答一个问题；不以漂亮无线热力图替代定量比较。

## 9 时间不足时的删减顺序

先删多楼层、开放词汇探索、多机器人与策略RL；再删压缩自适应、复杂服务调度和行人预测；之后决定是否删除3DGS增强或任务VOI。保留完整的信息隔离、公平基线、未知布局与失败报告。

可交付的三个层级：

- **4周原型：**参考RF＋确定性实例更新＋请求时间门控。只能说明流程可运行，不能声称算法优势。
- **8周核心研究：**部分观测下的可靠地图更新与预算补测，带强基线。任务仍可保持受控代理，贡献限定于已验证范围。
- **16周完整仿真研究：**加入实际合成视觉、固定验证器、网络复核和及时正确核验实验。是否达到论文标准由证据决定。

## 10 开始实施前固定的五项决定

1. 主实验坚持单AP、5 GHz Wi-Fi；任何NR实验单列，不混合指标。
2. 第一版固定图像编码、验证器和局部导航器，优先枚举候选动作。
3. 世界真值、可见观测和算法预测三者分离，按可用时间控制访问。
4. 3DGS接受平面／网格对照，不预设必要性；通信模型接受独立后端复核。
5. 先完成一个房间的可解释闭环，再增加场景规模；在无实验结果之前不写“实时”“显著提升”或“首次”。
