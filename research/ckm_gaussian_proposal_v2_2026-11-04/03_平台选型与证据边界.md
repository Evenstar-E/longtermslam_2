## 1 新增资料怎样改变研究定位

| 资料 | 可以借鉴什么 | 不能据此声称什么 |
|---|---|---|
| [ZONDA](https://arxiv.org/abs/2607.21025) | 把多视角目标核验作为明确任务模块；动态环境下核验证据需要维护 | 原文已评价网络受限核验；多视角选择本身是本方案创新 |
| [RFScape](https://arxiv.org/html/2411.18635) | 物体局部表示及变换复用，是必须面对的直接先例 | 首次发现物体搬移可以驱动RF更新 |
| [SuperMap](https://arxiv.org/abs/2608.22896) | 实例变化维护和层次地图接口 | 原文已经提供3DGS电磁地图或准确材料恢复 |
| [Sionna–Isaac闭环导航演示](https://arxiv.org/abs/2610.08618) | 传播与机器人仿真闭环及通信导航已有直接工作 | 将Sionna、Isaac和ROS 2连接起来就足够新颖 |
| [Isaac-Net](https://github.com/ZzZTripleZzZ/isaac-net) | 网络状态随机器人仿真推进，可作为快速实验后端 | 本项目已经具备动态感知CKM，或全部配置均被包级仿真验证 |

本版研究差异仍是一组假设：不完整观测下的实例不确定性是否能够更好地解释地图失效；任务相关补测是否比一般采样更有用；这种改进是否能传递到及时正确核验。必须用对照实验支持，不能只通过拼接模块名称证明。

**SuperMap源码状态补充（2026-11-04）：**论文／项目页有开放源码的表述，但本次实际打开的[官方仓库默认分支](https://github.com/superxslam/SuperMap)只显示README和doc，并有代码将在RSS之后发布的公告。README列出的examples与requirements等运行依赖未出现在可见根目录中。因此目前按“未确认可获得可运行官方源码”处理，不能把仓库存在、搜索摘要或运行说明当作开源实现已经可用的证据。本路线不等待官方发布；先验证CKM，再独立实现必要的实例管理功能。

ZONDA的多楼层和动态行人机制不整体搬入首版；本方案只选用多视角核验作为受控应用。没有核验到可用的官方实现时，应称“受ZONDA启发的任务模块”，而非“完整复现ZONDA”。

## 2 Isaac-Net：推荐使用，但按能力拆开

### 2.1 核验到的层级

仓库将自身定位为研究原型，README当前标注0.2.0；核心采用Python／PyTorch，reference后端可在CPU运行。它包含不同复杂度的网络模型及Isaac Lab适配层，不必先启动完整机器人环境才能尝试网络部分。[README](https://github.com/ZzZTripleZzZ/isaac-net)

下表是本项目的使用决定，不表示仓库为本项目完成了适配。

| 能力 | 本项目使用方式 | 实施前检查 |
|---|---|---|
| 简单延迟／丢包模型 | 调通请求门控，做低保真对照 | 是否保留请求ID、超时及字节统计 |
| Wi-Fi模型 | 优先检验单AP主任务原型 | 动态SNR／增益输入、图像消息大小、返回路径 |
| NR模型 | 可选5G扩展，单列实验 | 不复用Wi-Fi参数与结论 |
| 场景无线地图 | 参考导出和缓存格式 | 静态假设、地图边界、天线与坐标一致性 |
| 边缘计算模型 | 服务队列原型或接口参考 | 服务时间含义、请求完整性、可支持返回模式 |
| Isaac Lab适配 | 后期联动物理状态与网络步进 | 数据是否真正按交付时刻对下游开放 |

### 2.2 Wi-Fi不是完整包级模拟器

文档描述的是平均场竞争近似，保留若干DCF／EDCA机制，但省略部分相关性与信道细节，且以Wi-Fi上行为范围。文档同时注明若干验证表仍待修复后重新生成。因此只采用经过本任务检查的配置，并用ns-3检查关键结果。[Wi-Fi模型及验证状态](https://github.com/ZzZTripleZzZ/isaac-net/blob/main/docs/wifi.md)

具体建设任务是：明确图像请求怎样映射为网络消息；验证丢失、完整重组和deadline；记录队列与传输字节；补齐或限制返回路径。应用层自行分包不意味着后端自动获得完整802.11包级细节。

不要直接把NR的外部增益调用复制给Wi-Fi。已查看的NREngine中，显式pathgain_db输入还有多小区条件，单小区走位姿／SNR等分支；这说明即使同一工厂API，细节也与配置有关。[engine.py](https://github.com/ZzZTripleZzZ/isaac-net/blob/main/isaac_net/core/engine.py)

本机尚未验证Wi-Fi所需动态输入路径是否能直接使用。工作路线把它安排在第1周，而不是写成已解决问题。

### 2.3 静态无线地图与动态CKM分别是什么

场景导出链路将USD几何／材料转成Sionna输入并烘焙无线地图；文档明确地图静态，运行时另有遮挡处理。场景地图的复用还包含布局与缓存假设。[场景无线地图文档](https://github.com/ZzZTripleZzZ/isaac-net/blob/main/docs/scene-radio-map.md)

本项目需要额外完成两套不同工作：

1. **世界侧：**环境事件发生后，正确更新参考传播，产生网络仿真实际使用的信道。
2. **算法侧：**机器人只根据有限观测更新预测CKM，保留不确定性并据此行动。

世界侧可以使用离线事件快照，算法侧不能直接获得完整快照。把静态图读进网络引擎不等于实现其中任何一套动态更新。

### 2.4 版本与运行环境

本次查看的Isaac-Net集成文档记录了Isaac Sim 6.1、Isaac Lab 3.0和原生Windows 11测试组合；这是作者测试记录，不是本机兼容性证明。[集成文档](https://github.com/ZzZTripleZzZ/isaac-net/blob/main/docs/isaac-lab.md)

后续应固定实际采用的提交和依赖，保存可运行配置。Sionna的CPU／GPU后端和驱动能力也单独检查，不笼统承诺“全部放WSL2即可”。无需照抄作者机器路径、系统设置或大规模并行参数。

| [SimART](https://github.com/guchuanv-alt/SimART) | 无线、机器人／ROS相关数据和工具链 | 后续参考；不按即插即用Isaac插件规划 |

前期仓库核验中，Isaac-Net、LatencyNodes、asimov和Aerial仓库能找到明确许可证；factory-x与SimART尚未确认项目级许可证。因此后两者可以继续阅读，正式复用代码前应核清授权。公开可访问的代码不自动意味着可任意再分发。

LatencyNodes文档所述的测试版本与Isaac-Net当前集成版本不同，故不把两者同时安装作为路线起点。各项目详细能力可能随提交改变，正式实验以锁定版本的代码和本地结果为准。

## 4 Sionna与ns-3各自提供什么

**Sionna RT用于传播参考。** 几何、材料、收发位置和传播机制决定信道量；使用哪种平均方式、哪些交互、多少射线，需要在实验中写清。[Sionna RT技术说明](https://nvlabs.github.io/sionna/rt/tech-report/S1.html)

**ns-3用于协议过程的独立检查。** 传播损耗输入不能代替PHY／MAC、竞争、重传和队列模型；动态链路适配由本项目检查，不能假设节点移动后外部损耗矩阵会自动反映场景。[ns-3传播模型](https://www.nsnam.org/docs/models/html/propagation.html)；[ns-3 Wi-Fi模型](https://www.nsnam.org/docs/models/html/wifi.html)

本版的组合是“低成本后端负责迭代，代表性条件用独立后端复核”。这是一项工程与实验安排，不保证两个模拟器一致，也不能保证仿真结果自动迁移到真实无线环境。

## 5 最容易越界的八种表述

| 避免的表述 | 本版使用的准确表述 |
|---|---|
| 视觉识别到材质，就知道了通信性能 | 视觉提供材料先验，RF参数仍需不确定性表达与观测约束 |
| 物体高斯跟着移动，信道地图就准确更新 | 位姿更新后重新评价传播交互，并检验残差与失效 |
| 有4D图就能知道未来遮挡 | 只有明确预测模型及有效期时才做短时外推 |
| Sionna给出了通信时延 | Sionna提供传播量，请求时延还需要协议、队列与服务过程 |
| Isaac-Net已经接好真实图片上传 | 其接口能力需要映射为本任务的图像完整交付与服务门控 |
| 预测地图变好了，所以任务必然更好 | 地图误差与任务收益分别检验，并控制视图／字节预算 |
| 已验证实时性能 | 需本机端到端耗时、积压和负载测量；目前未知 |
| 这个组合是首次提出 | 尚无穷尽新颖性证据，应与直接相关工作比较后再判断 |

## 6 结果与主张的对应关系

| 若最终只有这些证据 | 可以写的结论 | 尚不能写 |
|---|---|---|
| O/P轨道地图结果 | 给定或受控误差实例状态下的更新方法 | 机器人自主视觉建图已验证 |
| V轨道但使用真值位姿 | 合成视觉、已知定位下的实例地图更新 | 完整SLAM定位鲁棒性 |
| 单网络后端任务收益 | 在该模型和条件内有效 | 协议无关或真实网络有效 |
| 两后端但无真实无线实验 | 对所检查模拟器差异具有一定稳健性 | 已证明sim-to-real迁移 |
| 高斯与网格无差异 | 实例管理／风险决策可能有用 | 3DGS是主要性能来源 |
| RMSE降低但任务无收益 | 地图层面的改善 | 提高了目标核验效率 |
| 只改善成功请求时延 | 已交付请求的条件统计 | 全体请求的尾风险降低 |
